# xray 项目概览

> 分析对象：`chaitin/xray` 仓库（截至本地快照）
> 分析目的：为自研爬虫/安全扫描类项目提供架构与工程借鉴

## 1. 项目是什么

xray 是长亭科技出品的**综合性 Web 安全评估工具**，核心能力是：

1. **爬虫**：主动爬取目标站点的 URL、表单、参数
2. **被动代理**：监听本地端口作为 HTTP(S) 代理，分析浏览器/App 产生的流量
3. **漏洞扫描引擎**：对爬到的每一个请求/参数组合，跑一遍内置检测插件（XSS、SQLi、命令注入、目录扫描、SSRF、XXE 等）
4. **PoC 规则引擎**：基于 YAML + CEL 表达式的漏洞验证 DSL，支持社区众包提交漏洞规则
5. **报告生成**：将扫描结果渲染成单文件 HTML 报告

**关键认知（必须先明确，否则会误判这个仓库）**：

> 本仓库**不包含 xray 主程序（爬虫内核 + 扫描引擎）的源代码**。README 中明确写道"xray系列不开源，直接下载构建的二进制文件即可，仓库内主要为社区贡献的 poc"。

也就是说，这是一个**闭源核心 + 开源生态**的项目结构：

```
┌─────────────────────────────────────┐
│  xray 主程序（闭源二进制，不在本仓库）  │
│  - 爬虫引擎 / 被动代理 / HTTP 客户端    │
│  - 插件调度、并发调度、扫描状态机        │
│  - PoC/YAML DSL 的解释执行器（Go+CEL） │
└──────────────┬────────────────────────┘
               │ 加载 / 输出
               ▼
┌─────────────────────────────────────┐  本仓库开源的部分
│  pocs/           352 个漏洞验证规则(YAML) │
│  fingerprints/   指纹识别规则(YAML)       │
│  webhook/        Python 插件化 Webhook 接收服务 │
│  report/         Vue2 单文件 HTML 报告前端 │
│  tests/evilpot/  反误报测试靶场(Go)        │
│  tests/vulstudy/ 12 个开源靶场的一键 docker 编排 │
│  .github/workflows/ PoC 质量门禁 CI       │
└─────────────────────────────────────┘
```

这个结构本身就值得借鉴：**把最有价值、最需要保护的核心算法（爬虫+扫描引擎）闭源，把"规则数据"和"生态配件"开源**，用社区力量持续供给规则，同时不泄露引擎实现。这是安全产品商业化的典型打法（类似 Nessus / AWVS 的插件与内核分离模式）。

## 2. 目录职责一览

| 目录/文件 | 语言 | 定位 | 是否本仓库开源 |
|---|---|---|---|
| `pocs/` | YAML (DSL) | 352 条漏洞 PoC 规则，社区众包 | ✅ |
| `fingerprints/` | YAML (DSL) | 服务/组件指纹识别规则 | ✅ |
| `webhook/` | Python (Flask) | 接收 xray 主程序推送的漏洞数据，插件化二次处理（如通知钉钉、写数据库） | ✅ |
| `report/` | Vue2 + ant-design-vue | 把 JSON 扫描结果渲染为可交互的单文件 HTML 报告 | ✅ |
| `tests/evilpot/` | Go | 专门设计用来"诱导"扫描器产生误报的靶场，用于验证插件的抗干扰能力 | ✅ |
| `tests/vulstudy/` | Docker Compose | 聚合 12 个经典漏洞靶场，供 PoC 编写者验证脚本 | ✅ |
| `.github/workflows/check_poc.yml` | GitHub Actions | 下载官方二进制，跑 `poclint` 对所有 PoC 做 5 类静态检查 | ✅ |
| `docs/` | 静态 HTML | 文档站点跳转页 | ✅（外壳） |
| xray 主程序本体 | Go（推测） | 爬虫、扫描调度、DSL 解释器 | ❌ 闭源 |

## 3. 核心数据规模

- PoC 规则数：**352** 个，全部 `transport: http`，`manual: true`（即默认需要手动/主动触发，不在被动扫描中自动跑，避免误伤）
- 内置检测模块（从 README 表格统计）：**17 个社区版模块 + 4 个高级版模块**（XSS、SQLi、命令注入、目录枚举、路径穿越、XXE、PoC 管理、文件上传、弱口令、JSONP、SSRF、基线检查、任意跳转、CRLF、XStream、Struts2、ThinkPHP、Shiro、fastjson）
- 反连（DNSLog/HTTP 回连）能力被至少 10 个 PoC 使用，用于验证 RCE/SSRF 类无回显漏洞

## 4. 使用形态（三种扫描模式）

```bash
# 1. 主动爬虫模式：给一个入口 URL，自动爬取全站再扫描
xray webscan --basic-crawler http://example.com --html-output vuln.html

# 2. 被动代理模式：监听端口，分析所有经过的流量（含浏览器、App、脚本流量）
xray webscan --listen 127.0.0.1:7777 --html-output proxy.html

# 3. 单点模式：只测一个 URL，不爬虫（适合 CI/CD 集成、精确复测）
xray webscan --url http://example.com/?a=b --html-output single-url.html
```

这三种模式覆盖了安全扫描的完整使用场景：**面 (爬虫全站) / 流 (代理旁路) / 点 (单URL精确验证)**，这个三分类思路本身对爬虫类工具的模式设计很有参考价值。
