## 1. 模块定位

### 1.1 职责定义

目录扫描模块（`DirScanner`）是一个原子扫描能力，负责通过字典爆破发现 Web 服务器上的隐藏路径、敏感文件、备份文件、配置暴露和管理面板。

**输入**: 已发现的 HTTP/HTTPS 服务（IP:Port 或 域名:Port）
**输出**: 命中的路径列表 + 状态码 + 响应大小
**触发条件**:
- **主动触发**: 用户执行 `neoAgent scan dir -t target -p 80`
- **Pipeline 触发**: `scan run` 全流程编排中，ServiceScanner 识别出 Web 服务后自动触发
- **ServiceDispatcher 触发**: 分发器在端口服务扫描完成后向 Web 服务发起目录扫描

### 1.2 原子性边界

遵循"原子扫描器隔离原则"，`DirScanner` 不依赖 `WebScanner` 或 `ApiScanner` 的内部实现：
- `DirScanner` 有独立的包 `internal/core/scanner/dir/`
- 字典管理有独立的包 `internal/core/scanner/dir/dict/`
- 可复用 `internal/pkg/utils/` 下的无状态纯函数（如字符串处理、正则工具）

### 1.3 与相关模块的关系

```
                    ┌──────────────┐
                    │  RunnerManager│  ← 统一注册
                    └──────┬───────┘
                           │  Execute(task)
                           ▼
              ┌────────────────────────┐
              │    DirScanner           │
              │  internal/core/scanner/dir/
              └──┬──────────┬──────────┘
                 │          │
    ┌────────────▼──┐  ┌───▼──────────┐
    │  内置字典库    │  │  外部规则文件  │
    │  (嵌入式)      │  │  (可动态加载)  │
    └───────────────┘  └──────────────┘
```

**与其他扫描器的协作**:

| 上游 | 下游 | 协作方式 |
|------|------|---------|
| ServiceScanner | DirScanner | ServiceScanner 识别出 80/443/Web 端口后，Pipeline 触发 DirScanner |
| WebScanner | DirScanner | Web 页面中发现 `/admin`、`/api` 等路径，可追加到 DirScanner 队列 |
| DirScanner | VulnScanner | DirScanner 发现 `/wp-admin`、`/phpmyadmin` 后，VulnScanner 针对性加载模板 |

### 2.2 数据流

```
DirScanner.Run(ctx, task)
  │
  ├── 1. 初始化
  │     ├── dictionary.New() → 加载内置字典 + 扩展令牌
  │     ├── engine.NewRequester() → 配置超时/代理/限速
  │     └── scanner.New() → 初始化通配符检测
  │
  ├── 2. 并发调度
  │     ├── AdaptiveLimiter.Acquire() → 获取速率令牌
  │     └── goroutine 循环：
  │           path := dict.Next()      → 从字典迭代器获取下一个路径
  │           resp := requester.Do()   → 发送 HTTP 请求
  │           filter.Match(resp)       → 第一层：快速过滤
  │           scanner.Check(path)      → 第二层：通配符检测
  │           → match? → collectResult()
  │
  └── 3. 返回 DirResult
```

## 3. 字典管理设计

### 3.1 字典来源

| 来源 | 路径 | 说明 |
|------|------|------|
| **内置字典** | `dict/wordlists/`（`go:embed` 嵌入） | **直接复用 dirsearch 全部字典**：`dicc.txt` + `categories/` + `templates/` + `blacklist/`，编译时嵌入二进制，零配置启动 |
| **用户自定义字典** | `rules/dir/custom/*.txt`（运行时加载） | 用户自行放置的字典文件，运行时扫描加载，**免重新编译**，参考 `web_fingerprints.json` 加载范式 |
| **递归扫描** | `Dictionary.addExtra()` | 递归过程中发现的子路径自动加入扫描队列 |
| **动态扩展** | `Dictionary.addExtra()` | Pipeline/ApiScanner 发现的路径追加 |

**设计决策**: 直接复用 dirsearch 的字典文件，不重新编写。理由：
- 零成本验证字典质量，dirsearch 多年积累的黑产路径覆盖已足够成熟
- 唯一需要做的是 Go 语言重写字典加载器（双队列 + 模板扩展 + .gz 支持）

### 3.2 字典目录设计原则

**两层分离，职责清晰：**

| 层 | 路径 | 加载方式 | 修改后是否需要重新编译 | 面向对象 |
|---|------|---------|:---:|------|
| **内置字典** | `internal/core/scanner/dir/dict/wordlists/` | `go:embed`，编译进二进制 | ✅ 需要 | 开发者维护，跟随版本发布 |
| **用户字典** | `rules/dir/custom/` | 运行时 `os.ReadFile`，启动时扫描 | ❌ 不需要 | 用户/运维，热更新立即生效 |

**为什么内置字典不放在 `rules/` 下？**

`go:embed` 不支持 `../` 跨目录引用，字典文件必须在 `internal/` 包目录内才能被编译嵌入。`rules/` 只存放运行时可热更新的规则，两者不混用，避免出现像 `nmap-os-db` 那样"改了 `rules/` 下的文件，线上行为毫无变化"的维护陷阱。

**内置字典规模**（来源 dirsearch `db/` 目录）：

| 文件/目录 | 说明 |
|---------|------|
| `dicc.txt` | 主字典，核心通用路径，约 20K+ 条 |
| `categories/` | 按技术栈分类（php/java/python/infra 等共 30+ 文件） |
| `templates/` | 按场景分类（admin/api/auth/db/logs 等共 7 个文件） |
| `blacklist/` | 400/403/500 错误路径黑名单（命中时直接跳过，不输出） |
| `user-agents.txt` | 随机 User-Agent 池（供 `--random-agent` 使用） |

总计预计 50K-100K 条路径。通过 `--max-entries`（默认 500K）限制递归膨胀后的实际扫描量。

### 3.4 模板令牌系统

支持以下令牌（精简版 dirsearch 设计）：

| 令牌 | 含义 | 示例 |
|------|------|------|
| `%EXT%` | 扩展列表 | `.php`, `.asp`, `.html`, `.bak` |
| `%SUBJECT%` | 用户/账户相关 | `user`, `users`, `account`, `profile`, `login` |

**扩展模式**:
- **经典（默认）**: 仅替换 `%EXT%`，不存在的行原样使用
- **force_extensions**: 对无扩展路径，追加 `/.ext` 和 `/{line}.ext`

> ⚠️ **`overwrite_extensions` 不实现**：使用场景有限，`force_extensions` 已覆盖大部分需求，见参数设计文档 3.2 节。

**实现细节**:

```go
// 模板扩展
func expandTemplate(line string, extensions []string) []string {
    tokens := extractTokens(line)
    if len(tokens) == 0 {
        return []string{line}  // 无令牌，直接返回
    }
    
    // 对含 %EXT% 的行，笛卡尔积展开
    var results []string
    for _, ext := range extensions {
        result := strings.ReplaceAll(line, "%EXT%", ext)
        results = append(results, result)
    }
    return results
}
```

## 4. 通配符检测引擎设计

### 4.1 核心算法

移植 dirsearch 的 `Scanner` + `DynamicContentParser` 算法，Go 语言实现：

```go
type Scanner struct {
    // 采样池：path → []Response
    samples map[string][]Response
    // 静态模式：path → []string（保留词）
    staticPatterns map[string][]string
    // 是否静态（所有样本完全一致？）
    isStatic map[string]bool
    // 自校准指纹池
    fingerprintThreshold int
}

// Check 检测一个路径是否为通配符响应
func (s *Scanner) Check(path string, response Response) (bool, string) {
    // 1. 如果是已知通配符，直接跳过
    if s.isWildCard(path) {
        return false, "wildcard"
    }
    
    // 2. 如果还没有采样，开始采样
    if !s.hasSamples(path) {
        s.sample(path)  // 发送 path + randStealthWord × 2
        return true, "sampling"  // 采样阶段不输出
    }
    
    // 3. 比对静态模式
    if s.compare(path, response) {
        return true, "match"
    }
    
    // 4. 模糊通配符检测
    if s.isProbableWildCard(response) {
        s.markWildCard(path)
        return false, "probable_wildcard"
    }
    
    return true, "unique"  // 命中的路径
}
```

### 4.2 静态模式提取

```go
// extractStaticPatterns 提取两个响应中保留的共同词
func extractStaticPatterns(resp1, resp2 string) []string {
    // 1. 归一化：移除 UUID、长 hex、base64、时间戳
    norm1 := normalizeDynamic(resp1)
    norm2 := normalizeDynamic(resp2)
    
    // 2. 按空格分词
    words1 := strings.Fields(norm1)
    words2 := strings.Fields(norm2)
    
    // 3. 提取共同词（类似 difflib.Differ 的逻辑）
    var common []string
    diff := compareWords(words1, words2)
    for _, token := range diff {
        if token.Type == Common {
            common = append(common, token.Text)
        }
    }
    return common
}

// compare 比对新响应是否匹配已知模式
func (s *Scanner) compare(path string, response Response) bool {
    patterns := s.staticPatterns[path]
    if len(patterns) == 0 {
        return false
    }
    
    body := normalizeDynamic(response.Body)
    
    // 检查是否包含所有静态模式
    for _, pattern := range patterns {
        if !strings.Contains(body, pattern) {
            return false
        }
    }
    
    // 如果词数明显更多，检查相似度
    wordCount := len(strings.Fields(body))
    baseCount := len(s.baseWordCount[path])
    if wordCount > baseCount*1.35 {  // 长度差异 > 35%
        return false
    }
    
    return true
}
```

### 4.3 归一化函数

```go
// normalizeDynamic 移除动态内容
func normalizeDynamic(content string) string {
    // 1. UUID → [UUID]
    reUUID := regexp.MustCompile(`[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}`)
    content = reUUID.ReplaceAllString(content, "[UUID]")
    
    // 2. 长 hex → [HEX]
    reHex := regexp.MustCompile(`[0-9a-f]{32,}`)
    content = reHex.ReplaceAllString(content, "[HEX]")
    
    // 3. 时间戳 → [TS]
    reTS := regexp.MustCompile(`\d{10,}`)
    content = reTS.ReplaceAllString(content, "[TS]")
    
    // 4. Base64 → [B64]
    reB64 := regexp.MustCompile(`[A-Za-z0-9+/]{40,}={0,2}`)
    content = reB64.ReplaceAllString(content, "[B64]")
    
    return content
}
```

### 4.4 自校准

```go
// autoCalibrate 对高频指纹自动加入黑名单
func (s *Scanner) autoCalibrate(path string, response Response) {
    fp := fingerprint(response)  // (status, type, redirect, bodyLen/64, hash[:4096])
    s.fingerprints[fp]++
    
    if s.fingerprints[fp] > s.fingerprintThreshold {
        s.wildCardFingerprints = append(s.wildCardFingerprints, fp)
    }
}

func fingerprint(resp Response) string {
    // 类似 dirsearch 的 response_fingerprint()
    bodyHash := sha256.Sum256([]byte(resp.Body[:min(4096, len(resp.Body))]))
    return fmt.Sprintf("%d|%s|%d|%d|%x",
        resp.StatusCode,
        resp.ContentType,
        len(resp.Body)/64,
        bodyHash[:4],
    )
}
```

## 6. HTTP 请求器设计

### 6.1 路径保留机制

Go 的 `http.Client` 默认会对 URL 路径做 URL-encoding，需要自定义 `RoundTripper` 保留原始路径：

```go
// PathPreservingRoundTripper 保留原始请求路径，不做 URL-encoding
type PathPreservingRoundTripper struct {
    base http.RoundTripper
}

func (t *PathPreservingRoundTripper) RoundTrip(req *http.Request) (*http.Response, error) {
    // 使用 req.URL.RequestURI() 获取原始 target
    // 而非 req.URL.Path（会被 requests 库标准化）
    return t.base.RoundTrip(req)
}
```

### 6.2 请求配置

```go
type RequesterConfig struct {
    Timeout    time.Duration  // 请求超时（默认 10s）
    MaxRetries int            // 最大重试次数（默认 2）
    Proxy      *url.URL       // 代理配置
    Method     string         // HTTP 方法（默认 GET，与 dirsearch 一致）
    Headers    map[string]string
    UserAgents []string       // 随机 User-Agent
    RateLimit  int            // 每秒最大请求数（0 = 不限）
}
```

**设计决策**: 默认 GET 方法，理由：
1. 通配符检测需要完整响应体（body 比对），HEAD 无 body
2. dirsearch 默认就是 GET（`config.ini: http-method = get`）
3. 某些服务器对 GET/HEAD 返回不同响应，GET 更可靠
4. 后续可考虑提供 `--method HEAD` 作为轻量模式选项

### 6.3 重试与错误处理

```go
func (r *Requester) Do(path string) (*Response, error) {
    for i := 0; i <= r.config.MaxRetries; i++ {
        resp, err := r.sendRequest(path)
        if err == nil {
            return &Response{...}, nil
        }
        
        // 分类错误：DNS/超时/SSL/连接拒绝
        if !r.shouldRetry(err) {
            return nil, err  // 不重试的错误
        }
        time.Sleep(backoff(i))  // 指数退避
    }
    return nil, fmt.Errorf("max retries exceeded for path %s", path)
}
```

## 7. 并发调度设计

### 7.1 Worker 池

```go
func (s *DirScanner) Run(ctx context.Context, task *model.Task) (*DirResult, error) {
    // 1. 解析参数
    opts := parseDirOptions(task.Params)  // task.Params → DirOptions

    // 2. 初始化字典和请求器
    dict := dictionary.New(opts)
    req := engine.NewRequester(opts)
    
    // 2. 创建结果 channel
    results := make(chan *model.DirScanResult, 1000)
    
    // 3. 启动 Worker 池
    var wg sync.WaitGroup
    for i := 0; i < opts.Threads; i++ {
        wg.Add(1)
        go func() {
            defer wg.Done()
            s.worker(ctx, dict, req, results, opts)
        }()
    }
    
    // 4. 等待完成 + 关闭 channel
    go func() {
        wg.Wait()
        close(results)
    }()
    
    // 5. 收集结果
    var dirResult DirResult
    for r := range results {
        dirResult.Add(r)
    }
    
    return &dirResult, nil
}

func (s *DirScanner) worker(ctx context.Context, dict *dictionary.Dictionary,
                            req *engine.Requester, results chan<- *model.DirScanResult, opts *DirOptions) {
    for {
        path, ok := dict.Next()
        if !ok {
            return  // 字典耗尽
        }
        
        // 速率限制（复用 AdaptiveLimiter）
        s.limiter.Acquire(ctx)
        
        resp, err := req.Do(path)
        if err != nil {
            continue  // 请求失败，跳过
        }
        
        // 过滤管道
        if !s.filter.Match(resp, path) {
            continue  // 被过滤，跳过
        }
        
        // 通配符检测
        isMatch, reason := s.scanner.Check(path, resp)
        if !isMatch {
            continue  // 通配符响应，跳过
        }
        
        // 收集结果
        select {
        case results <- &model.DirScanResult{...}:
        case <-ctx.Done():
            return
        }
        
        // 递归扫描（参考 dirsearch 三种模式）
        if opts.Recursive && s.shouldRecursion(resp, path, opts) {
            subpaths := s.generateSubpaths(path)
            dict.AddExtra(subpaths...)
        }
    }
}

// shouldRecursion 判断是否对该路径进行递归扫描
func (s *DirScanner) shouldRecursion(resp *Response, path string, opts *DirOptions) bool {
    // 基础递归 (-r): 命中目录状态码（200/301/302/403 且以 / 结尾）
    // 深度递归 (--deep-recursive): 命中路径的每级目录也加入扫描
    // 强制递归 (--force-recursive): 任何命中路径都加入扫描
    
    if opts.DeepRecursive {
        // 例: /api/users 命中 → 追加 /api/ 和 /users/
        return true
    }
    if opts.ForceRecursive {
        // 任何命中的路径都递归
        return true
    }
    // 基础递归：仅对目录类型路径递归
    return strings.HasSuffix(path, "/") && isDirectoryStatus(resp.StatusCode)
}

// generateSubpaths 生成子路径（用于深度递归）
func (s *DirScanner) generateSubpaths(path string) []string {
    // /api/users/ → [/api/, /users/]
    parts := strings.Split(strings.Trim(path, "/"), "/")
    var subpaths []string
    for i := 1; i < len(parts); i++ {
        subpaths = append(subpaths, strings.Join(parts[:i], "/") + "/")
    }
    return subpaths
}
```

## 12. 待讨论问题

### 12.1 字典来源策略（已决定：复用 dirsearch 字典）

**决策**: 直接复用 dirsearch 的字典文件，不重新编写。

- 内置字典 = dirsearch `db/dicc.txt` + `db/categories/` + `db/templates/` 全部内容
- 编译时通过 `embed` 嵌入到二进制（与 NeoAgent 现有的指纹规则库加载方式一致）
- 外部规则文件可通过 `rules/dir/` 目录追加
- 好处：零成本验证字典质量，dirsearch 多年积累的黑产路径覆盖已足够成熟
- 唯一需要做的是 Go 语言重写字典加载器（双队列 + 模板扩展 + .gz 支持）

### 12.2 递归扫描（已决定：支持，参考 dirsearch 三种模式）

**决策**: 支持递归扫描，参考 dirsearch 的三种递归模式。

| 模式 | 含义 | dirsearch flag | NeoAgent 对应 |
|------|------|---------------|---------------|
| **基础递归** | 对找到的目录路径自动继续扫描 | `-r` / `--recursive` | `--recursive` |
| **深度递归** | 对每个目录深度继续扫描（`api/users` → 扫描 `api/` 和 `users/`） | `--deep-recursive` | `--deep-recursive` |
| **强制递归** | 对每个找到的路径（不只是目录）都继续扫描 | `--force-recursive` | `--force-recursive` |

**递归深度限制**: 参考 dirsearch `config.ini` 默认 `max-recursion-depth`，建议默认 3 层，可配置上限。

**递归状态码**: 参考 dirsearch 默认 `100-999`，建议 NeoAgent 默认只扫描 `200-399` 和 `403`（排除 404/500 等无效路径）。

**递归风险评估**: 
- 最大字典膨胀 = 基础字典 × 递归深度 × 命中目录数
- 如果 5K 字典 × 3 层 × 10 个命中目录 = 150K 路径（可控）
- 通过 `wordlist_max_size`（默认 500K）防止失控

### 12.3 默认请求方法（已决定：GET）

**决策**: 默认使用 **GET** 方法，与 dirsearch 保持一致。

理由：
- dirsearch 默认就是 GET（`config.ini: http-method = get`）
- 通配符检测需要完整响应体（body 比对），HEAD 响应没有 body
- 某些服务器对 GET 和 HEAD 返回不同响应，GET 更可靠
- 后续可考虑提供 `--method HEAD` 作为轻量模式选项（仅返回状态码，不做 body 分析）
